# EXP-028 — serial-console discovery findings

**Documented:** Containerlab commit5ae50094a3afd70e4e1674fe5385e64d8979da26, runtime/runtime.go ContainerRuntime interface, offers container inspection, exec, logs and events but no dedicated serial-console discovery method. runtime/generic_container.go GenericContainer contains generic port bindings and node/container identity, not console identity or exhaustive console inventory. This is scoped source inspection, not a claim about every external integration.

**Documented:** docs/manual/kinds/generic_vm.md describes the VM serial console via Telnet TCP5000 separately from container bash and guest SSH. nodes/generic_vm/generic_vm.go sets VirtRequired=true. docs/manual/kinds/srl.md documents bash and management CLI/SSH; these are not serial-console evidence. docs/manual/gui/vsc-extension.md node.telnetPort configures a Telnet action; it does not attest a live serial console. Six exact source files were compared byte-for-byte with the pinned Git objects; hashes are in static-results.json.

**Inferred decision:** native inspection should establish the node identity, while a separately reviewed, image-specific discovery adapter establishes the serial backing (for example a QEMU serial/chardev mapping). A generic TCP probe cannot distinguish a serial console from another service and can consume sessions; do not scan ports or write negotiation bytes as discovery. Do not infer absence for Linux or SR Linux solely from native kind.

**Observed static verification:**12 independent proposed-state cases pass, covering documentation/open-port/shell hints, unknown identity, missing adapter, qualified positive evidence, exhaustive versus partial empty inventory, error, stale evidence and replacement conflict. These are synthetic state-contract checks, not adapter/runtime qualification. Build/typecheck and5 targeted Chromium workbench tests pass. The existing inspector now explains that a matched enrollment still lacks a qualified discovery adapter. Approved layout unchanged.
