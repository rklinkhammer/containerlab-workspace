Purpose:
Establish the supported operating envelope of our application's
native integration and GUI. We are not validating Containerlab
generally, forwarding correctness or universal corpus fidelity.

This task authorizes focused application changes, qualification
harnesses and newly created dedicated VMs deploying only reviewed
synthetic fixtures. Ordinary builds/tests must not create VMs.

1. Define independent expectations before execution.

   Select a small, progressive set of fixtures covering:
   - The existing three-node/four-occurrence baseline.
   - An intermediate size.
   - The declared maximum of eight nodes, sixteen links and
     thirty-two endpoint occurrences.

   Use only qualified Linux and SR Linux profiles and existing
   immutable image pins. Include parallel links, multiple interfaces
   and a disconnected node where compatible with the selected size.

   Verify selected SR Linux ports against pinned native support.
   Do not invent aliases or expand supported kinds.

   Record exact expected node/link/endpoint identities, associations,
   unsupported outcomes and per-node failure behavior. Define sample
   counts, latency/output measurements and pass criteria before runs.
   Preserve fixture bytes, IDs and hashes.

2. Measure the complete collection path.

   Measure separately:
   - Native and Linux subprocess count, elapsed time and output.
   - Host transport and DTO validation.
   - Browser refresh completion and responsiveness.

   Report sample count, median, tail and maximum values with enough
   context to interpret them. Do not treat one successful collection
   as a capacity qualification.

   Verify native/interface inventories are batched per node rather
   than per endpoint. Disconnected nodes must not trigger unnecessary
   interface inspection.

   Retain current limits unless evidence justifies a documented
   change: six-second aggregate collection, 256 KiB combined output,
   one active collection, bounded refresh/polling and freshness.

   If maximum-size collection cannot meet these limits, report a
   supported lower envelope or a precise blocker. Do not silently
   raise budgets or weaken acceptance criteria.

3. Exercise partial failures and resource boundaries.

   Verify:
   - A stopped or absent node.
   - One node's failed or malformed interface inspection.
   - Missing and ambiguous alias evidence.
   - A slow inspection, deadline exhaustion and oversized output.
   - Cancellation, overlapping refresh attempts and recovery.
   - Namespace/interface changes and full container replacement.
   - Maximum-size acceptance and one-over-limit rejection.

   Distinguish actual native/runtime transitions, injected process
   failures, mocked output and contract-only tests.

   A local inspection failure must preserve other valid observations
   and all declarations when the collection budget permits. A global
   deadline/output failure must not publish a misleading fresh or
   complete snapshot. Prior observations must remain explicitly stale
   or historical.

   Preserve the established rule: stopping a namespace can remove
   its veth peer even when the peer container remains running.

4. Verify the GUI at the qualified sizes.

   Ensure node and link inspectors retain exact occurrence identity,
   parallel links remain distinct, disconnected nodes show container
   state, and partial failures have specific safe reasons.

   Verify keyboard navigation, selection retention, freshness,
   cancellation, superseded-response rejection, bounded rendering
   and malicious text handling.

   Do not add unrelated visual polish or operational controls.
